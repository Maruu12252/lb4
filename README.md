## Аналіз початкового коду та виявлені помилки

1. **Критична помилка: Спільна черга повідомлень (`inbox` як атрибут класу)**
   - **Опис:** Змінна `inbox = []` оголошена на рівні класу `Process`, а не всередині конструктора `__init__`. Це означає, що всі процеси (екземпляри класу) ділять одну спільну "скриньку".
   - **Важливість (Критична):** Порушення властивості **happens-before**. Якщо Процес A надсилає повідомлення Процесу B, це повідомлення потрапляє у спільну чергу. Якщо Процес C викличе `recv_one()` раніше за B, він "вкраде" чуже повідомлення. Локальний час Процесу C оновиться некоректно, а Процес B ніколи не отримає повідомлення і його годинник відстане.
2. **Менш критична помилка: Використання `pop(0)` для черги**
   - **Опис:** Виклик `self.inbox.pop(0)` на звичайному списку Python (`list`) не є потокобезпечним (якщо система масштабуватиметься на багато потоків) і має алгоритмічну складність $O(N)$, що призводить до падіння продуктивності при великій кількості повідомлень.
   - **Важливість (Менш критична):** Не впливає на логіку годинника Лемпорта безпосередньо, але робить код неоптимальним і небезпечним для багатопотокового середовища.

## Виправлення
- Змінну `inbox` перенесено в конструктор `__init__` як локальний атрибут екземпляра класу (`self.inbox = queue.Queue()`).
- Замість звичайного списку використано потокобезпечну структуру `queue.Queue()`, яка дозволяє надійно відправляти та отримувати повідомлення.
- Відношення `happens-before` тепер коректно зберігається, оскільки повідомлення ізольовані за адресатом.
